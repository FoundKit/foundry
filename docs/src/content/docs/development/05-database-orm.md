## 1. Multi-Database SPI Configuration

Configure your database connection in `.env`:

```bash
# postgres | mysql | mariadb | mongodb
DATABASE_TYPE=postgres
DATABASE_URL=postgres://postgres:postgrespassword@localhost:5432/foundry
AUTO_MIGRATE=true
```

## 2. Code-First Entity Schemas

In `SubsystemModule::orm_models`:

```rust
use foundry::prelude::*;

impl SubsystemModule for ShopSubsystem {
    fn slug(&self) -> &'static str { "shop" }
    fn display_name(&self) -> &'static str { "Shop" }

    fn orm_models(&self) -> Vec<EntitySchema> {
        vec![
            // Orders Master Table
            EntitySchema::new("shop_orders")
                .column(ColumnDef::bigint("id").primary_key().auto_increment())
                .column(ColumnDef::varchar("system_id", 32).not_null())
                .column(ColumnDef::varchar("order_no", 64).not_null().unique())
                .column(ColumnDef::varchar("customer_name", 64).not_null())
                .column(ColumnDef::decimal("total_amount", 12, 2).not_null())
                .column(ColumnDef::varchar("status", 24).not_null())
                .column(ColumnDef::json("items_payload").default_empty_json())
                .column(ColumnDef::datetime("created_at").default_current_timestamp())
                .column(ColumnDef::datetime("deleted_at").nullable())
                .index(IndexDef::new("idx_orders_sys", &["system_id", "deleted_at", "status"])),

            // Products Table
            EntitySchema::new("shop_products")
                .column(ColumnDef::bigint("id").primary_key().auto_increment())
                .column(ColumnDef::varchar("title", 128).not_null())
                .column(ColumnDef::decimal("price", 10, 2).not_null())
                .column(ColumnDef::integer("stock").not_null())
                .column(ColumnDef::datetime("created_at").default_current_timestamp())
                .column(ColumnDef::datetime("deleted_at").nullable())
        ]
    }
}
```

> [!TIP]
> **One-Command Scaffolding**:
> Run `foundry system new <slug> --with-table --table-name <table_name>`, and the CLI will instantly scaffold the complete template including `deleted_at` soft deletion, ORM entities, DTOs, services, and CRUD controllers!

### 2.1 Multi-Table Support & Post-Launch Schema Additions

A frequent question from developers is: *“Can a subsystem declare multiple physical tables? What if I need new tables months after launch?”*

The answer is: **Fully supported natively!**

* `SubsystemModule::orm_models(&self) -> Vec<EntitySchema>` returns a dynamic `Vec`. You can declare 1, 5, or dozens of tables (e.g. `shop_orders`, `shop_order_items`, `shop_products`, `shop_inventory_logs`) in a single subsystem.
* **Adding Tables Later**: If your system has been running for months and you need a new refund table `shop_refunds`, simply append `EntitySchema::new("shop_refunds")...` to the `vec![]` array in `orm_models()`.
* **Automatic Dev Sync**: When `AUTO_MIGRATE=true` in `.env`, the framework verifies existing database tables on startup. Detecting that `shop_refunds` is missing, it **automatically runs `CREATE TABLE IF NOT EXISTS` for seamless zero-downtime additions**!

### 2.2 Modifying Fields & Hybrid Schema Best Practices

The fields generated by the CLI (like `title` and `content`) are purely starting scaffolds. **Entity schema fields are never locked; you can freely add, remove, and customize columns**:

1. **Three-step code update**:
   * Add/remove `.column(...)` calls in `orm_models()`;
   * Add/remove corresponding typed fields in `models/mod.rs`;
   * Update request/response DTOs in `dto/mod.rs`.
2. **Hybrid Schema Best Practice (Relational + JSON)**:
   For systems that require high relational performance yet also need flexible ad-hoc custom fields, use the **“Core Physical Columns + JSON Metadata”** pattern:
   ```rust
   EntitySchema::new("shop_orders")
       // Core indexed & financial columns -> strongly typed physical columns + B-Tree indexes
       .column(ColumnDef::bigint("id").primary_key().auto_increment())
       .column(ColumnDef::varchar("order_no", 64).not_null().unique())
       .column(ColumnDef::decimal("total_amount", 12, 2).not_null())
       .column(ColumnDef::varchar("status", 24).not_null())
       .index(IndexDef::new("idx_orders_status", &["status", "created_at"]))
       // Flexible extensible attributes -> reserved JSON payload column
       .column(ColumnDef::json("extra_metadata").default_empty_json())
       .column(ColumnDef::datetime("deleted_at").nullable())
   ```
   * Fast status filtering and financial calculations run over indexed columns;
   * Custom campaign tags, delivery notes, or external channel parameters live in `extra_metadata` without schema alterations.

### 2.3 Exporting Complete DDL for Custom Models

`foundry ddl -d mysql` exports the 7 core platform tables. To export DDL for custom subsystem tables:
* **Via Scaffolding**: `foundry system new <slug> --with-table --db mysql` automatically writes `migrations/mysql/<slug>.sql`.
* **In-App Full DDL Export**: In your application after registering subsystems, call `foundry_storage::compile_all_ddl`:
  ```rust
  let full_mysql_ddl = foundry_storage::compile_all_ddl(foundry_storage::Dialect::MySql);
  println!("{}", full_mysql_ddl);
  ```

## 3. Fluent Query Builders (ORM Query Builder)

```rust
use foundry::prelude::*;

// 1. Paginated Select with Soft Delete filter
let (sql, binds) = OrmSelect::from_table("shop_orders")
    .column("id")
    .column("order_no")
    .column("total_amount")
    .where_eq("system_id", "shop")
    .where_null("deleted_at")
    .order_by_desc("created_at")
    .limit(20)
    .offset(0)
    .to_sql(Dialect::Postgres);

// 2. Insert
let (insert_sql, binds) = OrmInsert::into_table("shop_orders")
    .value("system_id", "shop")
    .value("order_no", "ORD-20261015-001")
    .value("customer_name", "Alice")
    .value("total_amount", 299.00)
    .value("status", "pending")
    .to_sql(Dialect::Postgres);

// 3. Soft Delete Update
let (soft_del_sql, binds) = OrmUpdate::into_table("shop_orders")
    .set_now("deleted_at")
    .where_eq("order_no", "ORD-20261015-001")
    .to_sql(Dialect::Postgres);
```
